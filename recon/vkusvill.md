# ВкусВилл (vkusvill.ru) — разведка 2026-10-31

Сайт на Битриксе, рендерит всё на сервере. JSON API для каталога нет: листинг и
карточку парсим из HTML (там есть JSON-LD `Product`). Перед сайтом стоит Qrator
(cookie `qrator_msid2`), но JS-челленджа нет: httpx с обычным UA с russia-03 получает 200.
За прогон разведки сделано ~90 запросов, по 1–2 в секунду, 429 и капчи не было.

Подвох в выборе магазина, см. «Магазин». Сделать это анонимно получилось 6 раз,
потом сервер начал отвечать «Сессия истекла» на все попытки с этого IP.

## Заголовки и cookies

Хватает `User-Agent` десктопного Chrome и `Accept-Language: ru-RU`. Cookies
(`__Host-PHPSESSID`, `SERVERID` — sticky-бэкенд `bitrix01..05`, `uguid`,
`qrator_msid2` с Max-Age=1000) сервер выставляет сам на первый GET, их нужно держать
в одном `httpx.Client`. Для `/ajax/*` дополнительно шлём `X-Requested-With: XMLHttpRequest`,
`Referer` и `Origin: https://vkusvill.ru`. `robots.txt` запрещает `/ajax/`, `*/?*`
(то есть пагинацию) и `/goods/set-*`.

## Магазин

От выбранной точки зависят и цена, и ассортимент. Выбор хранится в PHP-сессии
на сервере, отдельной cookie для него нет, так что каждой точке нужна своя сессия.

Как выбрать точку (фронт делает то же самое через Vue-модалку «Самовывоз»):

```
GET  /goods/                      → sessid из <input name="sessid" id="sessid" value="…">
POST /ajax/address_way/service_apply.php   (form-urlencoded)
     addr=<hintContent магазина>  addr_id=  lat=<…>  lon=<…>  dwh=
     shop_no=<snopNo / NOMER_TT>  type=shops  type_service=3
     route_comment=  new_service=  new_slot=  sessid=<…>
→ {"success":"Y",...}
```

- `shop_no` — это номер ТТ (`snopNo`/`NOMER_TT`, например `9889`), а не Bitrix-`id`.
  Если передать `id` (`5804640`), сервер отвечает «Не удалось установить адрес доставки».
- Без `addr` ответ — «Выберите магазин».
- `type=delivery` + `type_service=1` переключает на доставку (сам запрос не проверял).
- После 6 успешных выборов все следующие вызовы, в том числе из настоящего
  Chromium через Playwright и через curl прямо с russia-03, получали
  `{"success":"N","errorText":"Сессия истекла, обновите страницу"}`. Свежий `sessid`,
  повтор через ~15 минут и предварительный `ma_loader.php` не помогли. Похоже на
  лимит анонимных сессий/корзин с одного IP: в начале на первый GET сервер ставил
  `BXVV_SALE_UID`/`_ab`, после блокировки перестал. **Сессию с выбранной точкой
  нужно беречь (сохранять cookies на диск и переиспользовать) и проверять, сколько
  длится блок.**
- В одной точке (`9934`, ул. Дорожная) после выбора каталог почти пуст:
  в `/goods/` два раздела, `/goods/molochnye-produkty-yaytso/` → 404. Нерабочие
  или тёмные точки придётся отбраковывать по числу разделов.

### Проверка цен по точкам (Москва, «Молочные продукты, яйцо», стр. 1)

| Сессия | Корней в `/goods/` | Совпало с анонимом | Цена |
|---|---|---|---|
| аноним | 51 | — | базовая |
| 9805 (Доброслободская, «только для курьеров») | 47 | 19 из 24 | 13 из 19 дешевле на 2–10 ₽ |
| 9889 (Украинский б-р, 7) | 43 | 22 из 24 | 15 из 22 дешевле |

Между 9805 и 9889 у 17 общих товаров цены совпали один в один (яйцо С0 143 у обеих
против 145 у анонима, молоко 3,2% 90 против 93). Ассортимент первой страницы
отличается (5–7 позиций), состав корневых разделов тоже. Вывод: цены, вероятно,
одинаковы в пределах города или ценовой зоны, а аноним видит другую цену (скорее
всего доставки). Наличие и ассортимент зависят от точки. Данные —
`scratchpad/vkusvill/shop_vs_anon_listing.json`. Проверить 3-ю точку не удалось
из-за блокировки.

### Справочник магазинов

| Что | Запрос |
|---|---|
| Все магазины с координатами | `GET /ajax/address_way/get_shops.php` (XHR) → JSON-массив 1942 GeoJSON `Feature`: `id` (Bitrix), `snopNo` (номер ТТ — его отдаём в `shop_no`), `geometry.coordinates` [lat, lon], `properties.hintContent` («г. Москва, б-р Украинский, д. 7»). 859 в Москве, 235 в СПб, всего 273 населённых пункта. Ответ ~1 МБ, ходит одним запросом |
| То же с адресом и часами | `POST /ajax/address_way/modals/shops_find/sf_loader.php?class=` body `loadJS=Y&loadAssets=Y&firstLoad=Y` → HTML 2,9 МБ; JS-переменная `shopListItemsAP={"<id>_2":{ID,LAT,LON,CITY,ADDRESS,METRO,WORKHOURS,NOMER_TT,RATE,WILL_OPEN,OPENING_DATE}}` (1944 шт). В HTML есть фильтры формата («ВкусВилл Мини», «Даркстор», «Грейстор»), но в данных к точкам формат не привязан |
| Страница `/shops/` | та же разметка, 1672 точки (`data-id`, `data-id-tt`, `data-lat/lon`) |

Эндпоинта «ближайшие к координате» нет: `find_stores(lat, lon)` делаем сами,
расстоянием по `get_shops.php`.

### Остатки товара по магазинам (без сессии)

`GET /ajax/product_load_map_rests.php?id=<товар>&quantity=undefined&mode=map_load_region&latitude=<lat>&longitude=<lon>&distance=<м>&addr=`
→ `{"shop_points_features":[{id, geometry.coordinates, listItem:{RESTS:"7 шт"}}]}`.
Для сметаны 14526 в радиусе 5 км от центра — 143 магазина (130 из них есть в
`get_shops`), остатки 1–13 шт. При `distance=44636` (так шлёт фронт) — 1560 точек,
0,7 МБ. Без `mode` ответ — HTML-карта с `shopListItems` (+`RESTS`). Это наличие
на полке конкретной ТТ на один товар, цены там нет. Обходить так весь каталог дорого,
годится только для точечных проверок.

## Категории

`GET /ajax/header_catalog_menu/get.php` (XHR, 1,2 МБ HTML) — меню каталога целиком:
984 ссылки `/goods/<root>/<lvl2>/<lvl3>/`. Без подборок `set-*` остаётся
849 узлов: 39 корней, 416 узлов 2-го уровня, 394 3-го, 763 листа. Численный `data-id` есть
только у корней (`50388` — «Молочные продукты, яйцо»), у подкатегорий в меню только slug.
На странице раздела id лежит в `<input id="js-catalog-section-id" value="50388">`.
id категории = путь slug. В корнях смешаны товарные разделы и промо (`khity`,
`supermarket`, `set-novinki`, `idei-dlya-podarkov`, `kafe`…), товары в них
дублируются, поэтому категорию товара лучше брать из листинга: в
`js-datalayer-catalog-list-category` лежит путь «Молочные продукты, яйцо//Яйцо».
Список корней можно взять и из `/goods/` (51 ссылка вместе с `set-*`). После выбора
точки их становится меньше (43–47).

## Листинг

`GET /goods/<path>/?PAGEN_1=<n>` — HTML, по 24 товара на страницу.
Всего товаров — `<input id="js-catalog-page-param-total-products" value="516">`
(молочка: 21×24+12). Страница за последней отвечает `302`. Кнопка «Показать ещё»
грузит тот же URL через `$.ajax` и получает HTML-фрагмент. JSON-эндпоинта нет.

Карточка — `<div class="ProductCard js-product-v-tizer …" data-id="22658" data-xmlid="22658">`:

| Поле | Где |
|---|---|
| id | `data-id` (он же `sku`, он же хвост URL) |
| название | `.js-product-v-tizer__title-text`, вес/фасовка — `.js-product-v-tizer__title-weight` («10 шт», «250 г») |
| url | `href="/goods/yaytso-kurinoe-s0-22658/"` |
| цена | `<span class="js-datalayer-catalog-list-price hidden">145</span>` — **рубли**, целые |
| старая цена | `js-datalayer-catalog-list-price-old` (без скидки равна цене; пример скидки: 100 / 115) |
| весовой | после цены `/кг` вместо `/шт`; `data-koef` — средний вес штуки (бананы 1.1), `data-step` — шаг (0.1–0.5 кг) |
| картинка | `.ProductCard__imageImg src` (`img.vkusvill.ru/pim/images/mp/Mini_Square/<uuid>.jpg`) |
| категория | `.js-datalayer-catalog-list-category` |
| алкоголь | `data-is-alco` |

Там же JSON-LD `{"@graph":[Product…]}` на все 24 позиции: `sku`, `name`,
`brand.name`, `image`, `offers.price` (руб), `offers.availability`, `aggregateRating`.
Проще парсить его, а старую цену и `/кг` брать из разметки. Отсутствующих товаров
в проверенных листингах не встретилось, все `InStock`. Видимо, листинг показывает
только то, что есть в точке или зоне.

## Карточка

`GET /goods/<slug>-<id>/` — HTML ~270 КБ. JSON-LD `Product`: `sku`, `brand.name`,
`description`, `offers.price`, `additionalProperty[]`:
«Вес/объем», «Пищевая ценность на 100 грамм. Ккал / Белки / Жиры / Углеводы»
(отдельные числа), «Состав», «Годен», «Условия хранения». Если поставщиков
несколько (яйцо 22658), КБЖУ отдельными числами нет: в одном поле
«Пищевая и энергетическая ценность в 100 г.» идёт текст по каждому поставщику
(«АО "…": белки 12.7 г, жиры 11.5 г, углеводы 0.7 г; 157.1 ккал»), состав — так же.

В HTML пары `.VV23_DetailProdPageInfoDescItem__Title` / `__Desc`: Описание, Годен,
Вес/объем, Аллергены, Условия хранения, Страна производства, **Бренд**,
**Изготовитель** (название и адрес, по поставщикам), Состав. Почти у всего бренд
«ВкусВилл», настоящий производитель указан в «Изготовитель» или «Поставщики: …».
